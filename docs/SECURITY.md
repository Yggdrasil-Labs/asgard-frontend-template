# 安全性

这个仓库是前端模板，因此当前安全重点主要在安全默认值、依赖卫生，以及避免把错误模式继承给未来产品团队。

## 当前范围

当前覆盖：

- 依赖与供应链卫生
- 客户端安全编码习惯
- 配置清晰性
- 发布流程纪律

当前不覆盖：

- 服务端鉴权
- 密钥轮换系统
- 后端 session 或 token 签发
- 数据库访问控制

## 安全原则

- 不要在源码中硬编码密钥
- 环境变量与配置假设应通过 `.env.example` 和文档明确表达
- 优先使用类型化、集中式的请求工具，而不是四散的网络代码
- 避免在公共组件里留下未文档化的逃生口
- 保持依赖更新且可追踪

## 相关位置

- `src/utils/api/`
  共享 HTTP 与请求工具层
- `.env.example`
  配置示例面
- `.github/workflows/`
  自动化与发布面
- `package.json` 与 lockfile
  依赖面

## 对贡献者的要求

- 如果功能新增了环境变量，必须补充文档
- 如果组件会渲染富文本或用户输入内容，要说明是否需要清洗
- 如果为基础设施或认证新增依赖，要解释为什么有必要

## 当前边界

因为这是模板仓库，很多真实业务应用中的安全问题被有意延后。
