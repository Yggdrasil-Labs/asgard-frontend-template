# 组件库策略

## 目的

说明可复用组件应如何演进。

## 当前可复用能力面

- `ProForm`
- `ProTable`
- `ProDialog`
- `ProDetail`
- `SearchBar`
- 图标与字段支持层工具

## 策略

### 组件应解决“重复问题”

如果一个行为只在单个页面有价值，就先留在局部。

### 共享协议优于复制粘贴的配置项

多个组件如果需要相似的 field、schema 或 query 语义，应优先复用共享协议，并只文档化一次。

### 公共 API 必须有稳定语义

公共 props、events、slots 和 expose 方法应尽量保持可预测语义。基线规则见 `docs/components/component-api-conventions.md`。

### 示例页应真正使用契约

每个组件至少应有一个示例页或测试面，展示其推荐用法。

### 文档与测试是组件的一部分

如果出现以下任一情况，组件工作都不能算完成：

- 公共 API 改了，但文档没更新
- 行为改了，但测试没覆盖
- 示例页已经不能代表推荐用法

## 反模式

- 只是某个页面私有需求的薄封装，却被伪装成公共组件
- 通过隐藏内部状态绕过公共 API
- 大量语义重叠但没有权威文档的大配置对象
- 在还没有第二个使用场景前就强行引入“共享基元”
