# 稳定性

在这个仓库中，稳定性意味着：贡献者持续修改代码时，仍然可以信任 shell、路由协议和公共组件基元保持一致行为。

## 稳定性目标

- 本地开发启动行为可预期
- schema 驱动路由能够稳定标准化
- shell 状态能随导航保持同步
- 公共组件不会悄悄偏离它们的文档契约
- 关键行为出错时，质量检查能尽早失败

## 主要机制

- `pnpm lint`
  保护代码质量与格式预期
- `pnpm type-check`
  保护 TypeScript 与 Vue 类型边界
- `pnpm test:e2e`
  保护关键浏览器流程
- `tests/unit/` 下的单元测试
  保护路由、store、工具函数与组件不变量
- GitHub Actions CI
  保护共享分支上的仓库健康度

## 关键区域

- `src/router/`
  路由标准化出错会连带影响菜单、标签页、标题和页面渲染
- `src/app/shell/` 与 `src/layouts/`
  小改动也可能波及整个应用外壳
- `src/stores/`
  这些 store 负责协调 shell 行为，隐式耦合风险较高
- `docs/components/`
  如果这里与实现漂移，即使代码“还能跑”，也会造成理解偏差

## 常见失效模式

- route metadata 增加后没有同步补齐标准化默认值
- 页面层 hack 绕过了 shell 状态流
- 公共组件 API 改了，但文档和测试没更新
- 样式调整不小心破坏了移动端 shell 行为

## 何时更新本文档

以下情况应更新：

- 新增了新的验证层
- CI 门禁发生明显变化
- shell 稳定性假设发生变化
