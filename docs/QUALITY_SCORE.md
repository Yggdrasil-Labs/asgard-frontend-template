# 质量评分

本文档提供一套质量评估维度，不是自动生成报表。

## 评分维度

### 1. 架构清晰度

检查问题：

- 事实来源边界是否清楚？
- 贡献者能否快速判断 shell 策略在哪里？
- 关键抽象是否命名明确且有文档？

### 2. 组件契约可靠性

检查问题：

- 公共组件文档是否真实反映 props、events、slots 和 expose？
- 共享协议是否被复用，而不是重复定义？

### 3. 关键行为测试覆盖

检查问题：

- shell 和 router 不变量是否有保护？
- 高价值流程是否有 Playwright 覆盖？
- 文档驱动的硬规则是否在必要时有测试兜底？

### 4. 文档可导航性

检查问题：

- 人和 AI 是否能在一两跳内找到正确文档？
- 长期事实与临时计划是否已分离？

### 5. 变更安全性

检查问题：

- 贡献者能否做定点修改而不轻易破坏其他层次？
- lint、type-check 与测试是否能提供有意义的反馈回路？

## 如何使用这套评分

适用于以下场景：

- 大型重构
- 架构复盘
- 将模板推荐给其他团队前的自检

如果某次改动导致质量下降，应把问题记录到 `docs/exec-plans/tech-debt-tracker.md`。

## 记录规则

默认只保留评分维度与使用方法，不直接写无时间锚点的结论。

如果确实需要记录某次评估结果，应补充：

- 评估日期
- 评估范围
- 证据来源，例如测试、CI、人工审查或具体文档
- 结论的适用时限或复查条件
